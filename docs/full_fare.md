# 一般全票與電子票證轉乘優惠

規則核對日期：2026-11-25。金額取自現有 `mrt_excel/fares.csv`，不改寫原始 CSV、JSON 或 GeoJSON。

## 本次範圍

支援 `full_fare`（一般全票，不折扣）與 `stored_value`（同一張悠遊卡／一卡通／icash 一般卡，套用符合條件的轉乘優惠）。不計學生／敬老／兒童等特殊票價、定期票或累計回饋。站內逾時停留、補票及罰款不在本次計算範圍；回傳的是規劃票價，不是實際閘門交易紀錄。

網頁新增「票卡與轉乘優惠」選單，預設一般電子票證。`RoutePlanner.query()`、`/api/route` 與 `/api/itinerary` 支援 `fare_mode`；未指定的程式呼叫仍預設 `full_fare`，維持舊介面行為。

## 計費規則

1. 北捷內部換線，按同一旅次起訖查表，不逐線或逐站相加。
2. 環狀線使用同一套北捷／環狀線起訖票價。大坪林 `G04 ↔ Y07`、景安 `O02 ↔ Y11`、頭前庄 `O17 ↔ Y18` 站內轉乘可併計。
3. 板橋 `BL07 ↔ Y16`、新埔／新埔民生 `BL08 ↔ Y17` 是指定站外轉乘組合。出閘後 20 分鐘內（含 1,200 秒）進入對應車站可併計；超過則拆成前後兩個旅次。單程票仍須遵守指定閘門規定。
4. 機場捷運獨立計費，跨北捷或環狀線時分段加總；同一起訖不因列車種類改變票價。
5. 三鶯線獨立計費，經頂埔 `BL01 ↔ LB01` 時分段加總。`BL02 → LB12` 為 `F[BL02,BL01] + F[LB01,LB12] = 20 + 35 = 55` 元。
6. 一般電子票證模式中，北捷與三鶯線經頂埔雙向直接轉乘、使用同一張符合資格的票卡，出閘至下一段入閘不超過 1 小時（含 3,600 秒），可減 8 元。上述永寧到鶯桃福德為 `20 + 35 - 8 = 47` 元；全票模式、超時、換卡或中斷轉乘則為 55 元。機捷、單搭三鶯線、北捷／環狀線內部轉乘不套用這筆 8 元折扣。

## 轉乘時間如何判定

`FareCalculator.calculate(steps)` 保留搭乘與步行的順序，不再先移除步行步驟。若指定站外轉乘的步行步驟提供 `gate_elapsed_s`，以此出閘到入閘時間判斷；否則以既有 `duration_s` 作為規劃估計，並在 `fare.assumptions` 明確註記。下一班列車的 `wait_s` 不算進 20 分鐘。

時間缺失、負數、非數值或未知轉乘連接，都不直接假定符合併計條件，回傳 `total_twd: null`。缺少整段起訖票價時也不以逐站或轉乘兩側票價拼湊。

`gate_elapsed_s` 是計費模組的輸入欄位，目前一般路線查詢沒有使用者實際刷卡時間，因此網站採預估步行時間。此修改不增加實際票證交易資料，也不改變最早抵達搜尋方式。

三鶯線優惠同樣優先使用 `gate_elapsed_s`，否則使用 `duration_s` 並顯示估計條件；不把下一段候車時間計入 1 小時。電子票證模式代表使用者選擇同卡直接轉乘；模組若收到 `same_card: false` 或 `interrupted_transfer: true`，不套用折扣。若這些條件或轉乘時間無法判定，保留已知的 `base_total_twd` 全票合計，將 `discount_twd`、`total_twd` 設為 `null`，不保證折扣。

`parts[].fare_twd` 保持原始分段全票，另外提供各段 `discount_twd`、`net_fare_twd`；`discounts` 列出適用／不適用／待確認原因。優惠不跨越其他搭乘區段，也不適用只有步行而未搭車的情境。

## 圖片案例對照

| 情境 | 全票計算 | 金額 |
| --- | --- | ---: |
| 北捷內部換線 BL12 → R15 | `F[BL12,R15]` | 20 |
| 環狀線 Y07 → Y20 | `F[Y07,Y20]` | 40 |
| 七張經大坪林轉十四張 G03 → Y08 | `F[G03,Y08]` | 20 |
| 中山經板橋轉頭前庄，站外轉乘不超過 20 分鐘 | `F[R11,Y18]` | 25 |
| 同一路線，站外轉乘超過 20 分鐘 | `F[R11,BL07] + F[Y16,Y18]` | 50 |
| 機捷 A1 → A22 | `F[A1,A22]` | 155 |
| 南港經台北車站轉機捷老街溪 BL22 → A22 | `F[BL22,BL12] + F[A1,A22]` | 185 |
| 三鶯線 LB01 → LB12 | `F[LB01,LB12]` | 35 |
| 永寧經頂埔轉鶯桃福德 BL02 → LB12，不套用優惠 | `F[BL02,BL01] + F[LB01,LB12]` | 55 |
| 同一路線，合適的一般電子票證同卡於 1 小時內直接轉乘 | `20 + 35 - 8` | 47 |

中山到頭前庄的最快路線可能經中和新蘆線，未必經板橋。站外轉乘測試使用明確指定的搭乘步驟，不以最短路線查詢代替指定路徑。

## 程式碼與測試

- `fare_calculator.py`：計費系統分類、轉乘期限判定、分段起訖查表與一般電子票證優惠。
- `route_planner.py` 的 `_fare()`：將既有路線步驟交給全票模組，保留 `status`、`parts`、`total_twd` 等介面。
- `map.html`、`itinerary_query.js`：票卡選單、全票／優惠／合計、分段明細及預估條件。
- `tests/test_fares.py`：圖片案例、正反方向、1,200／1,201 秒及 3,600／3,601 秒邊界、同卡條件、缺資料、API 與推薦呼叫回歸。
- `tests/test_fare_ui.cjs`：兩種票卡模式的表單參數與金額、折扣及待確認提示。

在專案目錄執行 `python -B -m unittest discover -s tests -v`。前端顯示測試可執行 `node tests/test_fare_ui.cjs`。
