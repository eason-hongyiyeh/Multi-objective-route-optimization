### POI 資料真實性、11 家的由來及編號

店名、座標及有提供的地址來自實際 OSM 地圖紀錄，不是隨機生成的店家；但尚未逐店確認營業狀態、入口位置或是否漏店。因此「有真實資料來源」不等於「所有內容已核實正確」。
`poi_id`、`poi_type` 和查核狀態是專案整理欄位；`rating` 留空，不是假評分。

11 家不是預設上限：先取得矩形查詢範圍中的 115 筆 OSM 候選，排除不符合本次一般便利商店範圍的紀錄，再保留距任一現有站牌 100 公尺內的不同 OSM 店家，結果為 11 家。不同站牌可能連到同一家店，所以有 12 筆關聯。

P017、P040 原本只是歷史流水號。P001–P015 等早期地點刪除後，剩下的店家仍沿用舊編號；P040 是後來加入的店家，沒有排名、類別、距離或重要程度的意思。

## 100 公尺怎麼篩選

1. 用 Overpass 查詢涵蓋所有現有站牌的小範圍矩形內，所有 `shop=convenience` 的 node、way、relation；原始查詢與回應保存於 `sources/osm_convenience.json`。
2. node 採節點座標，way/relation 採 Overpass 回傳的包圍盒中心；中心不是店門口。
3. 排除已知不屬於本次範圍、未開放、已停用或缺少名稱的紀錄，理由保留於 `sources/excluded_osm_features.json`。
4. 逐一比對每個站牌與每家店，用 Haversine 大圓距離，地球半徑採 6,371,000 公尺。
5. 保留所有未四捨五入前距離 ≤ 100 公尺的配對，不截成一家、不為沒有結果的站牌配遠方店家。
6. 同一個 OSM 類型＋ID 共用一個 POI。不同 OSM ID 的實體重複店仍需人工查核。

這裡的「半徑」是地圖上的直線距離，不是可步行道路長度。直線在 100 公尺內，實際走路可能超過 100 公尺。
官方站位或店家入口一旦修正，是否在範圍內也可能改變。

## stop_poi_mapping.csv 是什麼

這是「站牌與店家的關聯表」，不是另一份店家主檔。每列代表一個站牌可以對應哪家 100 公尺內的店，以及步行資料。
`stop_id` 連到 `stops.csv` 查站名，`poi_id` 連到 `pois.csv` 查店名。同站可多店、同店可多站，因此不能只看列數就當作店家數。

例如：
- `S023,P001`：高雄車站 → 全家，直線約 46.846 公尺；步行端點待確認，分鐘數空白。
- `S023,P002`：同一站 → 另一家 7-Eleven，直線約 81.836 公尺；道路導航估計 4 分鐘。
- `S001,P009` 與 `S035,P009`：兩個不同站牌對應同一家 OK 超商。

## 步行時間怎麼取得

使用 [FOSSGIS 的 OSM 步行導航服務](https://routing.openstreetmap.de/about.html)，端點為 `routed-foot/route/v1/foot`，不是汽車導航。

| 欄位 | 意義 |
| --- | --- |
| `stop_id / poi_id` | 分別對應站牌主檔與店家主檔的識別碼 |
| `straight_distance_m` | 用原始站牌、店家座標計算的 Haversine 距離（公尺） |
| `route_distance_m` | 導航服務回傳的道路路徑距離（公尺） |
| `route_duration_s` | 導航模型回傳的耗時（秒），不是碼表實測 |
| `walking_time_min` | 通過端點檢查後，將 `route_duration_s / 60` 向上取整 |
| `start_snap_m / end_snap_m` | 原始座標到導航匹配道路端點的距離 |
| `time_status` | 導航估計、端點待查核、服務失敗或未量測 |
| `source / fetched_at` | 完整查詢網址、查詢時間 |

OSRM 依可步行道路與步行設定建立路網。服務公開的 [foot 設定](https://github.com/fossgis-routing-server/cbf-routing-profiles/blob/master/foot.lua) 包含預設速度 4.5 km/h 及路口等模型參數；本次直接保存服務回傳秒數，沒有自行用直線距離除以速度。無法僅憑公開程式確認伺服器部署的精確版本。

例如三鳳中街（S008）到 P005：
- 直線約 88.160 公尺，符合 100 公尺篩選。
- 導航道路距離 233.3 公尺，耗時 188.6 秒。
- `ceil(188.6 / 60) = 4`，所以填入 4 分鐘的道路導航估計。

每筆原始路徑幾何、秒數和端點保存在 `sources/walking_routes.json`，可以重現與人工核對。

**導航時間仍非真實實測時間。** 它不反映當下紅綠燈、個人速度、施工、室內通道及未被地圖記錄的入口。起終點會先匹配到道路，回傳路徑不包含原始座標到匹配端點的未確認連接路段；不能把它當成精準的站牌到店門口耗時。

本次品質檢查採用專案設定的 30 公尺端點偏移上限，並拒用零距離、零秒及「導航距離短於原始直線距離」的結果。這是查核門檻，不是官方精度保證。
S023 → P001 的原始直線約 46.846 公尺，但匹配後導航只有 38 公尺、30.3 秒，因此 `walking_time_min` 留空，狀態為 `endpoint_needs_review`；沒有直接當成 1 分鐘。

若需要實測，應從實際上下車站位走到店門口，記錄日期、方向、開始與結束時間，以及過街等待。分時段重複量測，保存原始秒數，才能說明典型耗時與變動範圍。回程也應另測，不能假設必然與去程相同。

## 公車時間：最高 50 km/h 的等加減速模型

本次按使用者指定，用距離與運動模型估算，已填入全部 54 個路段。**這不是實際公車車程或官方速限調查**；50 km/h 是本次統一設定的速度上限，不代表每一段道路都允許或能達到這個速度。

### 距離與假設

- 距離 `D`：從 `stops.csv` 的起終站座標算 Haversine 直線距離，地球半徑 6,371,000 公尺。尚未取得公車實際沿路線的長度，不用汽車導航路徑冒充。
- 速度上限 `V = 50 / 3.6 = 13.888889 m/s`。
- 起點及終點速度都為 0：假設每站都停車。
- 等加速度 `a = 1.0 m/s²`，等減速度大小也為 `1.0 m/s²`。此值是方便先建立對稱模型的設定，表示速度每秒增加／減少 1 m/s，不是測得的公車性能。
- 路段內只有一次起步與一次煞停；不含紅綠燈、塞車、轉彎降速、坡度、上下客停留、等車或轉乘。
- 直線距離及省略的延誤會使模型偏樂觀；請稱「模型估算」，不稱「真實時間」。

### 加速、減速從哪裡開始

由 `v² = 2as`，達到最高速的加速距離為：

```text
加速距離 = V² / (2a) = 96.450617 公尺
加速時間 = V / a = 13.888889 秒
減速距離 = 96.450617 公尺
減速時間 = 13.888889 秒
兩者所需總距離 = V² / a = 192.901235 公尺
```

因此不是任意規定「每站前固定幾公尺加速」，而是依速度上限與加速度算出：

1. **站距大於 192.901235 公尺：梯形速度曲線。** 從起站開始加速，前 96.45 公尺達到 50 km/h，中間等速；距終站 96.45 公尺時開始減速，到站速度為 0。
2. **站距小於或等於 192.901235 公尺：三角形速度曲線。** 加速走前半段，在中點轉為減速，後半段停到終站；短路段達不到 50 km/h，不能硬塞入兩段各 96.45 公尺。
3. 邊界剛好等於 192.901235 公尺時，最高速度恰好 50 km/h，但等速段長度為 0。零距離的模型耗時為 0。

### 時間公式

所有公式用公尺、秒計算，`a` 為加／減速度的正值大小。

```text
長路段：
  加速秒數 = V/a
  等速秒數 = (D - V²/a)/V
  減速秒數 = V/a
  總秒數 T = D/V + V/a

短路段：
  最高速度 v_peak = sqrt(a × D)
  加速秒數 = v_peak/a
  減速秒數 = v_peak/a
  總秒數 T = 2 × sqrt(D/a)

分鐘數 = T/60
```

例如 100 公尺的路段：前 50 公尺加速、後 50 公尺減速；最高速度只有 10 m/s（36 km/h），加速與減速各 10 秒，共 20 秒。

### 本次實際資料的例子

E001／88 路：福德市場（S032）→ 聖功醫院（S028）。

| 階段 | 距離 | 時間 |
| --- | --- | --- |
| 加速 0 → 50 km/h | 96.450617 公尺 | 13.888889 秒 |
| 等速 50 km/h | 76.038316 公尺 | 5.474759 秒 |
| 減速 50 → 0 km/h | 96.450617 公尺 | 13.888889 秒 |
| 合計 | 268.939551 公尺 | 33.252537 秒，約 0.554209 分鐘 |

本次 54 段中，37 段有等速階段、17 段不需要等速階段；模型時間約 15.94–79.38 秒。這些短秒數是理想化模型的結果，不能拿來代表含停等的實際營運速度。

### route_edges.csv 的模型欄位

| 欄位 | 意義 |
| --- | --- |
| `travel_time_min` | 模型分鐘數，保留 6 位小數供路線累加，不逐站向上取整 |
| `travel_time_s` | 模型總秒數 |
| `model_distance_m / distance_method` | 站距與距離算法，目前為 `haversine_straight_line` |
| `speed_cap_kmh` | 設定的速度上限，50 |
| `acceleration_m_s2 / deceleration_m_s2` | 加速及減速度大小，都是 1 |
| `peak_speed_kmh` | 該段實際達到的模型最高速度，可能小於 50 |
| `accel_distance_m / cruise_distance_m / decel_distance_m` | 三階段距離 |
| `accel_time_s / cruise_time_s / decel_time_s` | 三階段秒數 |
| `motion_profile` | `triangular` 三角形或 `trapezoidal` 梯形速度曲線 |
| `time_status` | `kinematic_estimate`，運動模型估算 |
| `source / model_version / computed_at` | 輸入與計算程式、模型版本、計算日期 |
| `legacy_test_time_min` | 舊版固定 2 分鐘，留存追溯，不參與計算 |
| `direction_status` | `unverified`；路線方向仍待官方核對 |

CSV 查詢程式已改為讀取小數分鐘；網頁顯示到小數點後兩位，避免把小於 1 分鐘的路段截成 0。可以使用已有有向連線產生模型行程，但不自動推造反方向的公車服務。

### 後續如何改成實際資料

先核對官方站位、路線及方向，再取得沿公車路線距離、官方站間時間或實測紀錄。實測需配對同班車、同方向的「下一站到站時間 − 上一站離站時間」，按平假日及時段整理；上下客、候車與轉乘另計。
[高雄市交通局路線總覽](https://www.tbkc.gov.tw/Service/PublicTransport/NewBusRoute)、[TDX](https://tdx.transportdata.tw/) 可作為後續資料入口。本次模型沒有使用它們的站間實測值。

本次只調整 CSV 版，尚未同步 SQL 資料庫；SQL 版的整數時間讀取與欄位定義仍需另行調整才能保留小數分鐘。
目前 CSV 完整行程模型也還未納入實際等車、完整來回步行及採買耗時，因此畫面總時間不等於完整現實行程。

## 重新產生資料

在專案根目錄執行，僅使用 Python 標準函式庫：

```powershell
# 使用已保存的 OSM／導航快照重建，不連線
python csv_version/generate_convenience_store_data.py

# 更新 OSM，並查詢未快取的步行路徑（需要網路）
python csv_version/generate_convenience_store_data.py --fetch-osm --fetch-walking

# 明確要求將 POI 重新編成 P001 起算時，連同兩張關聯表重建
python csv_version/generate_convenience_store_data.py --renumber-pois

# 依站距更新公車模型時間（預設最高 50 km/h、等加減速度 1 m/s²）
python csv_version/estimate_bus_travel_times.py

# 只接受實測時，可將步行時間留空
python csv_version/generate_convenience_store_data.py --walking-mode unknown
```

工具會覆寫 POI、商品、兩張關聯表及涵蓋清單。手工補入的店家／價格應先另存，避免被快照重建覆寫。便利商店工具不會修改站牌座標或公車時間；公車時間由 `estimate_bus_travel_times.py` 另外產生。公車估算工具會覆寫全部路段的時間及模型欄位，未來補入實測值後請先備份，不要直接重跑覆蓋。
導航以完整查詢網址快取；重用時仍顯示原始下載時間，不假裝是最新結果。若要重查已存在路徑，先備份並移走 `sources/walking_routes.json`，再執行含 `--fetch-walking` 的指令。公共導航查詢依序執行，間隔至少 1.1 秒。
