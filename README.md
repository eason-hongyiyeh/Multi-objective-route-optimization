# 捷運資料地圖

將 `data/` 的車站、出入口、軌道與夜市顯示在網頁地圖上，左側以勾選表控制顯示，點選地圖可查看資訊。

## 檔案用途

| 檔案 | 用途 |
| --- | --- |
| `mrt_map.py` | 啟動本機網站、讀取圖層，提供人工校正資料的讀取與儲存 API。只使用 Python 標準函式庫。 |
| `map.html` | 地圖畫面、站名標籤、路線勾選表、夜市營業時間及出口配對檢查模式，載入人工校正介面。 |
| `manual_exits.py` | 分類缺漏出口、驗證人工輸入、另外儲存 GeoJSON，篩選可供步行計算的出口。 |
| `manual_exits.js`、`manual_exits.css` | 左側人工校正清單、地圖定位、編輯表單與已確認出口圖層。 |
| `data/exit_review_context.json` | 17 筆出口的來源連結、車站對照及參考座標，僅供導覽和人工比對。 |
| `data/manual_verified_exits.geojson` | 人工儲存的處理狀態、座標、來源與備註；不覆蓋原始出口檔。初始為空。 |
| `test_manual_exits.py` | 測試人工儲存、驗證、重新讀取與步行候選限制，所有寫入都在暫存資料夾。 |
| `calculate_market_walks.py` | 查詢步行路網，計算夜市到 20 分鐘內最近捷運站的路徑；資料更新後需重新執行。 |
| `walking/market_stations.json` | 夜市到最近捷運站的距離、時間及路線座標，供地圖使用。 |
| `data/mrt_station.geojson` | 158 筆具站名的車站位置，以及站碼、路網等來源欄位。 |
| `data/mrt_tracks.geojson` | 256 筆捷運資料：31 筆路線、225 筆路線節點（224 筆有停靠用途、1 筆未提供用途）。 |
| `data/airportmrt.geojson` | 117 筆機捷資料：70 筆軌道、3 筆普通車方向路線、44 筆停靠點。 |
| `data/nightmarket.geojson` | 35 筆夜市位置、名稱，以及補查的營業時間、來源與待確認說明。 |
| `nightmarket_hours.md` | 全部夜市的營業時間查詢表，包含來源連結與尚未確認的項目。 |
| `missing_exit_coordinates.md` | 17 筆缺少座標出口的來源 ID、車站對照及待確認清單。 |
| `data/mrt_exits.geojson` | 517 筆捷運出入口；500 筆有座標可顯示，17 筆缺少座標。已移除先前人工確認非出口的 5 筆，以及 LG09、LG10 共 5 筆施工出口資料。 |
| `data/airport_mrt_exits.geojson` | 36 筆機場捷運出入口，包含站名、站碼、出口代碼與設施資訊。 |
| `data/mrt_exits_clean.geojson` | 500 筆清理後出口，是 `assign_exit_station.py` 的輸入。 |
| `data/mrt_exits_with_station.geojson` | 500 筆出口的最近車站配對成果，保留站名、距離及配對狀態。 |
| `.gitignore` | 排除虛擬環境及 Python 快取。 |

## 開啟方式

在本資料夾執行：

```powershell
python mrt_map.py
```

瀏覽器會自動開啟。保持終端機開啟，按 `Ctrl+C` 關閉。若連接埠被占用，可用 `python mrt_map.py --port 0`；不想自動開啟瀏覽器可加 `--no-browser`。

點選夜市可看中文營業時間、來源連結與查詢日期。2026-10-19 查詢共找到 26 筆政府網站時段及 1 筆非官方報導；另外 8 筆因名稱不明、資料矛盾、未查得時段或曾公告停業而保留待確認。完整結果見 [夜市營業時間查詢表](nightmarket_hours.md)，查詢日期不代表現場營業確認日期。

地圖使用 [Leaflet](https://leafletjs.com/) 與 [OpenStreetMap](https://www.openstreetmap.org/copyright) 街道底圖，需要網路連線。

## 缺漏出口人工校正

啟動方式仍是 `python mrt_map.py`。如果舊服務還在執行，先按 `Ctrl+C` 關閉後重新啟動，再重新整理網頁。請透過程式顯示的本機網址開啟，直接開啟 HTML 無法儲存。

LG09 的 C1、C2 及 LG10 的 A、B、C 共 5 筆已依要求從專案出口資料及校正參考清單刪除。它們原先位於 `data/mrt_exits.geojson`；原始下載檔仍在 `D:\OSM\mrt_exits.geojson`，未修改。來源節點連結見 [移除資料來源紀錄](missing_exit_coordinates.md#已移除資料的原始來源)。

目前 17 筆都來自 `mrt_exits.geojson`，原檔 `geometry` 為 `null`，但同時有以下不同問題，並非只補座標就能使用：

| 問題 | 筆數與內容 |
| --- | --- |
| 原檔未提供座標 | 17 筆；另查得的 OSM 節點位置只作參考，未經人工確認。 |
| 未提供出口編號 | 4 筆：汐科北入口、淡江大學、淡金北新、竿蓁林。 |
| 車站歸屬仍需確認 | 5 筆：竿蓁林 1 筆、幸福 2 筆、新莊副都心 2 筆；清單會標明候選關係。 |
| 非捷運系統 | 1 筆汐科北入口，屬臺鐵；保留供人工處理，永遠不列入捷運出口步行候選。 |

以上問題可重疊。17 筆原檔均無座標，無法從原檔判斷座標精度。其他既有機捷出口的三位小數座標仍有精度限制，也不會因此被視為人工確認的出口。

操作方式：

1. 在左側「缺漏出口人工校正」點選一筆。地圖移至其車站附近；藍點是車站參考位置，灰點是 OSM 參考位置。目前 17 筆都有車站位置可供導覽，候選車站仍須人工確認歸屬。車站與來源參考點都不會自動填入出口座標。
2. 核對出口原名、來源 ID、站名與站碼；需要時展開「出口名稱與車站資料」修改。候選車站須由你確認，沒有編號可留空，不必猜測。
3. 按「開始在地圖定位」，在地圖點選實際出口位置。經度與緯度會填入欄位並畫出橘點，也可手動輸入 WGS84 座標。點選後定位模式自動結束，仍須儲存才會寫入檔案。
4. 選擇「已確認／待確認／查無座標／未營運或規劃中／非實際出口」。要選「已確認」，須有有效座標、車站名稱、交通系統、查證來源，並勾選「已核對實際出口位置及所屬車站」與「此出口已開放通行」。改動座標或站名後須重新勾選核對。查無座標時須清除手動座標；未營運及非實際出口須填寫判定來源或備註。
5. 填寫查證來源，例如官方出口圖網址、現勘日期及紀錄，再按「儲存此筆校正」。成功時顯示檔名與時間；已確認出口顯示為綠點，可用獨立勾選框開關。

重新設定座標：選取出口後按「清除座標」，可清空經緯度及目前編輯點；若原本已確認，會退回待確認，儲存後才會清除檔案中的正式座標並退出步行候選。按「清除並重新定位」則會同時開啟地圖選點模式，也可從已確認綠點的資訊視窗使用這個按鈕。選好新位置後，重新核對、選「已確認」並儲存即可取代舊位置。藍色車站點及灰色來源參考點仍可供比對；未儲存前原紀錄不變，可用「捨棄此筆未存變更並重讀」還原。

如何確認儲存成功：

- 點「查看已儲存 GeoJSON」，或在編輯器開啟 `data/manual_verified_exits.geojson`，以來源 `id` 查找該筆，檢查 `verification_status`、`verification_source`、`reviewed_at` 及座標。
- 重新整理網頁或重啟服務，再選同一筆，表單應顯示先前儲存的值與時間。只切換清單時保留的未存變更仍屬頁面草稿，必須按儲存。
- 正式 GeoJSON 座標順序是 `[longitude, latitude]`，即 `[經度, 緯度]`。只有「已確認」有 `geometry: Point`；其他狀態一律 `geometry: null`，暫存位置放在 `properties.draft_coordinates`。
- 原始欄位保留在 `original_properties`，來源參考資訊放在 `reference_context`。儲存只更新人工檔，不改寫 `mrt_exits.geojson`、機捷出口、清理檔或配對檔。檔案被鎖定或寫入失敗會顯示錯誤並保留舊檔；其他頁面已更新同筆時，會拒絕覆蓋並要求重讀。

後續出口步行計算請使用 `manual_exits.load_verified_exits(...)` 或本機 `/routing-exits.json`，只取得人工確認、已開放通行且屬於捷運／機捷／輕軌的有效出口點。篩選時重新驗證確認條件，不只相信 `routing_eligible` 旗標；撤回確認立即排除。現有步行程式也會拒絕未確認的出口終點。

**既有夜市步行結果仍是到「車站」，本次保留原功能，尚未改成到出口。** 原本有座標的出口仍照常顯示，但有座標或最近車站配對成功不代表已人工確認。校正檔最初為空，沒有代替你核准任何出口。

驗證程式：`python -m unittest -v test_manual_exits`。

## 地圖顯示

- 白心圓點表示車站，邊框依路線配色；同筆車站有多條線時使用深色邊框。
- 左側每條路線各有「站點」與「路線」勾選框；「全部」列可一次控制所有站點或所有線段。站點包含車站與路線節點。轉乘站只要任一所屬路線仍勾選站點，就保留顯示；未能分類的資料列於「未分類」。
- 新北投、小碧潭支線獨立控制，分別包含北投、新北投與七張、小碧潭的車站標記。
- 放大至第 14 級以上自動顯示可見車站的站名及站碼，隱藏站點時也會隱藏標籤。
- 路線末端自動裁切至車站在路線上的投影位置。僅修改畫面上的幾何，不修改 GeoJSON、站名或路線資訊。
- 機捷車站加上「機場捷運」區別同名站。側欄提供圖層勾選表與出口配對檢查開關。
- 點選車站可看站碼、路線、營運單位、地址與原始欄位；路線直接依 GeoJSON 站碼判別，不讀取舊 CSV。
- 同名但不同位置的車站資料各自保留。
- 夜市以桃紅色實心圓顯示，預設開啟；點選可看名稱、來源 ID、經緯度及來源提供的地址、營業時間、電話等。放大後顯示名稱。
- 夜市圖層目前只有點位，「路線」欄停用。
- 「捷運出入口」為藍色小實心圓、「機場捷運出入口」為紫色小實心圓，各自勾選顯示；「路線」欄停用。滑鼠移上可看名稱，點選可看出口編號、座標及原始欄位；機捷另顯示站名、站碼、位置說明及電梯等設施。
- 一般出口缺少完整的車站對照，不用鄰近車站猜測歸屬，也不把出口當成車站。500 筆可顯示出口中，有 81 筆未提供 `ref`；名稱若含編號仍保留顯示。17 筆缺座標的資料保留在原檔，另在左側人工校正清單分類處理。
- 機捷出口檔案更新日期為 2018-12-04，未包含 A22 老街溪站出口；座標只到小數點後三位，後續計算精確出入口步行路徑前需補齊及核對。此次只新增出口顯示，既有夜市步行結果仍到車站座標。
- `nightmarket.geojson` 只保留 35 筆夜市資料，程式直接顯示檔案中的點位。筆數是來源紀錄數，同一夜市的分區或不同物件可能重疊；不自動合併，也不讀取舊夜市 CSV。

車站與軌道三份檔案共 531 筆，全部具有效座標：158 筆車站、269 筆路線節點、94 筆線段及 10 筆多線幾何。加上 35 筆夜市及兩份出口資料，六份檔案共 1,119 筆，其中 1,102 筆可顯示，17 筆缺少座標。其中路線節點有 268 筆具停靠用途、1 筆用途未提供。不同檔案可能有重疊資料，筆數不等於不重複的車站數。圖資可能包含施工路段或不同更新時間的資料，不代表即時營運狀態。

捷運與機捷圖層支援 `LineString`、`MultiLineString` 路線及 `@relations` 成員資訊。線段、站點、資訊視窗色標及左側色標一律使用 `map.html` 的 `routeColors`，依提供的路網圖設定近似配色，不宣稱為官方精確色碼。文湖線棕色、淡水信義線紅色、松山新店線綠色、中和新蘆線橘黃色、板南線藍色、環狀線亮黃色、三鶯線淺藍色、機場捷運淡紫色、新北投支線粉紅色、小碧潭支線黃綠色。線條不透明，避免重疊造成深淺差異；原始 `colour` 欄位保留但不控制顯示。轉乘站採深灰色，未分類採灰色。街道底圖由 OpenStreetMap 提供，底圖配色不受此設定影響。

點選可看來源物件 ID、起訖、方向與成員用途；新北投及小碧潭支線會顯示支線名稱。來源的名稱與起訖欄位若互相矛盾，保留原始內容供核對。

小實心點表示路線節點，依所屬路線配色，多線共用節點採深色。以相同 OSM 節點 ID 對照 `mrt_station.geojson`，可補上 98 筆路線節點的站名、站碼；不以距離猜測。其餘缺少站名的停靠點會明確標示，沒有成員用途的節點不會當成停靠點。

`mrt_tracks.geojson` 與 `airportmrt.geojson` 有 47 筆相同來源 ID，原始資料各自保留，畫面依所屬路線統一控制顯示。以上筆數是資料筆數，不是去重後的站數。

## 出口配對檢查

有待確認資料時，啟動 `python mrt_map.py` 後可勾選左側「出口配對檢查」。預設關閉；每次開啟都會自動縮放到所有可顯示的 review 配對。沒有待確認資料時，整個檢查區塊隱藏。

- 紅色編號圓點是待確認出口，藍色圓點是 CSV 目前配對的車站；同一車站由多筆出口共用時，只顯示一個藍色標記。
- 每筆以虛線連接出口與車站，標籤顯示編號及距離（例如 `1 · 364.53 m`）。這是直線配對距離，不是步行路徑。
- 點紅色出口或虛線，可看出口編號、出口原名、配對車站、站碼、距離及兩端來源 ID；缺少的編號或名稱顯示「未提供」。點藍色車站可看所有連到該站的待確認出口。
- 車站座標以 CSV 的「配對車站ID」精確對照 `data/mrt_station.geojson`；不重新尋找最近車站，也不以同名站代替。缺少 ID、座標無效或讀檔失敗時，在左側提示原因。
- 取消勾選會一起隱藏檢查標記、虛線及距離標籤。此開關獨立於一般站點／路線開關，可先關閉其他圖層以方便檢查。
- 此模式只讀取及顯示，不寫回 CSV 或 GeoJSON，也不提供自動核准。修改檢查 CSV 或站點資料後，需重新啟動地圖。

一般出入口仍顯示原始出口檔；清理檔與配對成果不作為一般圖層重複繪製。`mrt_exits_clean.geojson` 保留供配對程式讀取，`mrt_exits_with_station.geojson` 保留配對成果。

未被後續程式使用的 `airport_mrt_exits_clean.geojson` 副本，以及已清空的 `exit_station_review.csv` 已刪除。沒有檢查 CSV 或待確認資料時，地圖隱藏出口配對檢查區塊；真正的讀檔或資料錯誤仍會顯示原因。日後重跑清理或配對程式，會重新產生對應檔案。

## 更新資料

夜市到捷運站的步行計算：

```powershell
python calculate_market_walks.py
```

- 起點使用 `data/nightmarket.geojson`，終點使用 `data/mrt_station.geojson`。按可步行路徑長度找最近車站，包含資料中的機場捷運站；每個夜市最多一條結果。
- 速度固定為每秒 1 公尺，上限 20 分鐘（含），即 1,200 公尺。超過上限不列入結果；夜市仍可點選，顯示「20 分鐘步行範圍內沒有捷運站」。
- 結果只存 `walking/market_stations.json`，不再產生 CSV。每筆保留夜市 ID、車站 ID、站名、站碼、路徑公尺數、秒數與路徑座標；若道路有時段限制會附註。檔案最外層保留資料核對碼、速度、上限及已計算夜市清單，避免誤用舊結果。
- 點選夜市可看最近捷運站、距離、時間，並顯示／隱藏步行路徑。
- 使用 [Valhalla](https://valhalla.github.io/valhalla/api/route/api-reference/) 的 `pedestrian`、`shortest=true` 查詢步行路網。直線距離只用來排除不可能更近的候選，不當成步行距離；不使用捷運軌道充當步行道路。
- 路由使用夜市與車站座標附近的可步行道路，未必是指定出入口；不含座標與道路的偏移、站內步行、停留或紅綠燈。超過 150 公尺的座標偏移、非步行路段或查詢失敗會中止計算。
- `walking/.cache/` 為重算用的路由回應快取，不供網站顯示；`--refresh` 可重新查詢路網。夜市或車站資料修改後，重新計算並重啟地圖；僅修改 `opening_hours` 或 `opening_hours_*` 時段欄位不影響路徑，重啟地圖即可。平常開啟地圖不會重新查詢。

端點裁切以同路線車站為候選，僅處理距端點 1 公里內、距路線 150 公尺內且沿線裁切不超過 1 公里的部分；不裁閉合線段、不刪除超過半條路線，也不延長原本未達車站中心的線。新北投與小碧潭支線分別限用其兩端車站。缺少適合車站時保留原線形，此功能為視覺整理，不代表真實軌道在車站處結束。

新增、修改、刪除或重新命名 `data/` 中的 `.geojson` 後，重新啟動程式並重新整理網頁。路線選項依實際載入的資料建立；出口檔案使用上述檔名，便可顯示在各自的勾選列。

資料需為 GeoJSON `FeatureCollection`，使用 WGS84 經緯度（經度在前、緯度在後）。支援點、線、面及其複合幾何。車站點依 `public_transport=station` 或 `railway=station` 辨識。缺少或無效座標會略過，檔案讀取失敗會顯示原因，原始檔不會被修改。

`taipei_mrt/` 與 `night_markets/` 的舊資料保留，目前程式不讀取。
